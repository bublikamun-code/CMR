## Этап 2 — Backend: общий модуль `_db()` (средний риск)

### 2.1. Создать `server_snapshot/db_utils.py`
```python
from database import get_tenant_db
from fastapi import Depends
from sqlalchemy.orm import Session
from database import get_db
import models
from auth import get_current_user

def resolve_tenant_db(current_user, db):
    """Единая логика выбора сессии для всех роутеров."""
    if current_user.tenant_id is None:
        return db  # superadmin или пользователь без тенанта → основная БД
    return get_tenant_db(current_user.tenant_id)
```

### 2.2. Заменить `_db()` в 6 роутерах (семейства A + B + C)
- `clients_router.py`, `card_details_router.py`, `suppliers_router.py`, `payments_router.py`, `writeoffs_router.py` — семейство A → `from db_utils import resolve_tenant_db as _db`
- `kanban_router.py` — семейство B (`not tenant_id`) → унифицировать на `is None`
- `activity_router.py` — семейство C → добавить параметр `db`, вернуть `db` для superadmin

### 2.3. Заменить `_get_db()` в 3 роутерах (семейство D)
- `custom_objects_router.py`, `workflows_router.py`, `webhooks_router.py`
- `_get_db(user)` → `resolve_tenant_db(user, db)` с передачей `db` через Depends

### 2.4. Inline в `email_parser_router.py` (семейство F)
- 3 места (строки 208, 461, 492) → `resolve_tenant_db(current_user, db)`

- После каждого этапа: `tools/deploy.sh back <file>` + `tools/deploy.sh restart`

## Риски
- **Backend без тестов** — каждая миграция проверяется вручную на production
- **deferred-close хак** — удаление до полной миграции сломает все хендлеры с ORM-relationships
- **78 finally-блоков** — массовое изменение, высокая вероятность регрессий
- **Этап 3 самый рискованный** — можно отложить, если Этапы 1-2 выявят проблемы
