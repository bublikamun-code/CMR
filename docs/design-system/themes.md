# Слои оформления

Интерфейс — это четыре слоя, наложенных друг на друга. Порядок и специфичность —
главное архитектурное правило CSS проекта.

```
1. База (светлая)   — :root + компоненты           style.css
2. Тёмная тема      — [data-theme="dark"] (0,2,1)  style.css
3. Liquid Glass     — html[data-glass="on"] (0,3,1) liquid-glass.css
4. Compact-режим    — .compact-mode                style.css
```

Переключатели: `crm_theme` (boot.js, localStorage), `crm_glass`
(localStorage; в boot.js glass включён ПО УМОЛЧАНИЮ — «off» надо задать явно),
compact — класс на `<body>`.

## База + тёмная тема

1. Новый цвет в компоненте = новая переменная в `:root` + её значение в
   `[data-theme="dark"]`. Хардкодить hex в правиле компонента запрещено.
2. Существующие точечные тёмные правила (`[data-theme="dark"] .something`) не
   удалять и не «упрощать», даже если после токенизации они кажутся избыточными:
   они перекрывают и старые литералы, и конкретные тени/градиенты.
3. `color: #fff` / светлый текст на тёмных поверхностях (сайдбар, шапки таблиц) —
   легитимен и не переносится на переменные текста.

## Liquid Glass (site/css/liquid-glass.css)

Опциональный режим «стекла» ПОВЕРХ обеих тем. Специфичность
`html[data-glass="on"] …` = (0,3,1) — старше тёмных правил (0,2,1), включая их
`!important`-фоны. Принципы из шапки файла обязательны:

1. **Blur только на «хроме»**: сайдбар, модалки, тосты, дропдауны, панель
   уведомлений. Одновременно 2–3 крупных blur-поверхности — больше нельзя
   (скролл канбана просядет). Карточки канбана — полупрозрачность БЕЗ blur.
2. **Mesh-фон на body** обязателен — без него блюру нечего преломлять.
3. **Фолбэки обязательны** для каждой новой стеклянной поверхности: строка в
   `@supports not (backdrop-filter)` и в `@media (prefers-reduced-transparency)`.
4. **rgba-альфы, градиенты mesh-фона и уровни blur — не токенизировать и не
   «нормализовать»**: это и есть дизайн режима, выверенный по фидбеку.
5. Единственное допустимое сближение с базой: статусные цвета через общие
   `--status-*` (значения совпадают в обоих файлах).
6. Чекбоксы/радио в glass исключены из полупрозрачных инпутов (собственная
   отрисовка галочки) — не «чинить».

## Compact-режим

`.compact-mode` уменьшает плотность таблиц и карточек. Новые табличные компоненты
обязаны иметь compact-правило, если у соседей оно есть; проверка любого
табличного изменения — в обоих режимах.

## Матрица проверки (минимальная)

Любое изменение стилей проверяется скриншотами как минимум: светлая / тёмная /
светлая+glass / тёмная+glass. Изменения таблиц — дополнительно в compact.
Базовые эталоны: `gui-test-screenshots/design-system-baseline/`.
