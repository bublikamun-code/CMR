# Принципы

Действуют, когда токены и компоненты молчат. Адаптация общих UI-принципов
(в духе typeui-fundamentals) под этот проект: CRM плотных данных, два магазина,
три роли.

## 1. Сетка и плотность

Шаг 4px (tokens.md §3). CRM избыточно плотных данных: плотность важнее воздуха.
Не «улучшай» интерфейс увеличением отступов — свободное пространство появляется
только на уровнях секций (`--space-lg/xl`), внутри карточек и таблиц — 4–12px.
Решения, увеличивающие высоту строки таблицы или карточки канбана, требуют
явного обоснования (compact-режим должен остаться плотнее обычного).

## 2. Иерархия

- Один `h1` на страницу (заголовок секции), далее — визуальная иерархия, не
  новые уровни тегов.
- Кегль 16px — заголовки страниц и карточных секций; 14px — база; 13/12 —
  данные; 11px и меньше — подписи и метки. Не повышать кегль, чтобы «выделить»:
  для выделения есть вес (600/700), цвет и фон.
- Один акцентный цвет — индиго. Семантические (danger/success/warning) — только
  по прямому смыслу (ошибка/успех/ожидание), не для декора.

## 3. Контраст и состояния

- Текст на софт-плашках — тёмный вариант из триады (`--*-soft-text`), не `muted`.
- Интерактивные элементы имеют все четыре состояния: default, hover (фон/цвет,
  без transform), active (`scale(0.97)` допускается), focus-visible
  (`var(--ring)`). Кнопка без реакции на наведение — дефект (см.
  docs/audits/UI_AUDIT_PLAN.md A.1).
- Анимации: 120–200ms, `--ease-out-strong`, без bounce/overshoot; entrance —
  один раз, циклические пульсации — только для живых статусов (sync).

## 4. Тёмная тема и стекло

Любой новый цвет живёт в переменных (themes.md). Проверка — в четырёх
комбинациях слоёв. Правило «одна кнопка темы — одна» и прочие продуктовые
решения glass — в шапке liquid-glass.css.

## 5. Платформа (CSP и статика)

- Сборки нет — статика как есть. JS-синтаксис проверяется `tools/check_js.sh`.
- CSP `script-src 'self'`: инлайн-`<script>` и onclick-атрибуты запрещены;
  обработчики — через `data-handler="Module.fn"` (делегирование) или addEventListener.
  Инлайн-атрибуты `style` разрешены (правило — components.md).
- Версионирование кэша: `?v=<sha1>` проставляет `tools/stamp_assets.py`;
  после правки css/js HTML-штампы обновляются этим скриптом, руками не править.

## 6. Доступность (цели проекта)

- Управление с клавиатуры: модалки закрываются Escape, дропдауны — кликом вне,
  фокус возвращается на триггер.
- Touch-цель интерактивного элемента — ≥ 32×32px (плотный CRM-компромисс вместо
  стандартных 44px; меньше — только для второстепенных иконок в таблицах).
- `prefers-reduced-*` уважается (см. фолбэки glass).

## 7. Стиль кода

- Комментарии и строки UI — по-русски; классы, переменные, id — по-английски.
- Комментарий в CSS/JS пишет тот, кто правит, только для неочевидных
  ограничений (контракт, причина); датированные «журнальные» шапки — по
  образцу существующих при существенных изменениях блока.
- Изменение внешнего вида существующего компонента не должно ломать его
  JS-контракты: классы, по которым ищет JS (`.inline-edit-cell`, `.cb-written-off`,
  `data-handler`, id), не переименовываются без правки всех упоминаний.
