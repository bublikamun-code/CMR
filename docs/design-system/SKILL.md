# Дизайн-система CRM «Свет в доме» — Agent Instructions

> **Скоуп: только legacy-фронт `site/`.** Основной фронт с 19.09.2026 — v2
> (`server_snapshot/site-v2/`, генерируется из `server_snapshot/tools/mockups/`).
> Визуальный канон v2 — токены в `<style>`-блоке прототипа и конвенции в
> `server_snapshot/tools/mockups/README.md` (включая раздел «Движение
> (конвенции)»); план работ — `docs/audits/V2-FIX-PLAN-2026-09-19.md`.
> Этот документ читай при правках замороженного `site/` (по договорённости).

Единственный источник правды о визуальном языке интерфейса. Система выведена из
фактического кода (site/css/style.css) и зафиксирована как канон: новые правки
подчиняются ей, а не соседнему старому коду.

## Load order

Читать модули в порядке:

1. [tokens.md](tokens.md) — цвета, типографика, отступы, радиусы, тени + таблицы
   «дрейф → канон» для нормализации.
2. [themes.md](themes.md) — модель слоёв оформления и правила их расширения.
3. [components.md](components.md) — инвентарь компонентных классов и правило
   инлайн-стилей.
4. [principles.md](principles.md) — базовые принципы, когда токены молчат.

## Conflict resolution

1. **Токены и компоненты** (tokens.md, components.md) — выигрывают в конкретных
   значениях (цвет, размер, отступ).
2. **Принципы** (principles.md) — выигрывают в структурных вопросах (иерархия,
   контраст, плотность).
3. **Доступность и CSP платформы** — высший приоритет всегда.
4. Дрейфующий код рядом с твоей правкой — не образец. Если старый код
   противоречит токенам, правь его к канону (в пределах своей задачи), а не
   копируй значения.

## When the design system is silent

Если значение не описано ни в одном модуле: шаг сетки 4px, шрифт Manrope,
акцент — индиго `--primary-color`, нейтральные — шкала slate. Новое значение
появляется в токенах ТОЛЬКО после того, как оно понадобилось ≥3 местам: до этого
используется ближайший канонический.

## Что система НЕ описывает

- Бизнес-логику фронта и API (см. README.md, docs/STATUS.md).
- Анимационное поведение в деталях (см. docs/audits/UI_AUDIT_PLAN.md — тайминги
  и easing уже выверены аудитом; существующие переходы не менять).
- Снятие `!important` в style.css — отдельная кампания с tools/css_cascade.py,
  в обычные UI-правки не вмешивается.
