# План доработок CRM «Снабжение и Продажи»

План по результатам аудита CRM (канбан-воронка, карточка сделки, задачи, финансы, клиенты, поставщики, дашборд, календарь, настройки). Задачи сгруппированы в спринты по приоритету. Четырёхосная разметка: **[Д]** дизайн, **[Ф]** функциональность, **[Л]** логика, **[U]** UI-опыт. Каждая задача имеет критерии приёмки.

---

## Спринт 0. Блокеры (данные и деньги — ошибаться нельзя)

### 0.1. Явное сохранение в карточке сделки [Ф][U]
- **Проблема:** в карточке сделки нет кнопки «Сохранить». Изменения полей (сумма, дата, email, клиент, магазин) фиксируются непонятно когда — при потере фокуса, при закрытии, или не фиксируются вовсе. Риск молчаливой потери данных.
- **Действия:** реализовать автосохранение с визуальным индикатором («Сохранено 14:32» / «Сохранение…» / «Ошибка сохранения — повторить») ИЛИ явную кнопку «Сохранить» с предупреждением при закрытии несохранённой карточки («Есть несохранённые изменения: Сохранить / Не сохранять / Отмена»).
- **Критерии приёмки:** изменение любого поля подтверждается индикатором; закрытие карточки с несохранёнными правками невозможно без явного выбора пользователя; при ошибке сети данные не теряются и есть повторная отправка.

### 0.2. Валидация суммы и даты [Ф]
- **Проблема:** поле «Итоговая сумма сделки» принимает 0 и произвольный текст; «Дата окончания» — свободный ввод «дд.мм.гггг» без маски.
- **Действия:** числовой ввод с маской и разделителями тысяч для суммы; date-picker + маска ввода для даты; подсветка ошибки с текстом («Введите сумму числом», «Некорректная дата»).
- **Критерии приёмки:** невозможно сохранить сумму «abc» или дату «32.13.2026»; при нулевой сумме сделки на этапах после «Новый запрос» — предупреждение «Укажите сумму сделки».

### 0.3. Разделить денежные потоки: «оплата клиента» vs «оплата поставщикам» [Л][Д]
- **Проблема:** бейдж «Не оплачен» в шапке и «Осталось оплатить 1 857,93 BYN» в чек-листе — два разных денежных потока (клиент платит нам / мы платим поставщикам) показаны без разделения и с противоречащими данными. Чекбоксы «Опл.»/«Приш.» в чек-листе без расшифровки.
- **Действия:** разделить карточку на два явных блока: «Оплата от клиента» (сумма сделки, оплачено, остаток, бейдж статуса) и «Закупка у поставщиков» (чек-лист позиций: заказано/пришло/оплачено нами). Переименовать чекбоксы в «Оплачен поставщику» / «Пришло на склад» с тултипами. Бейдж в шапке привязать к оплате клиентом: «Не оплачен / Частично / Оплачен».
- **Критерии приёмки:** пользователь по карточке без обучения отвечает на вопросы «сколько должен клиент» и «сколько мы должны поставщикам»; статус «Частично оплачен» появляется при 0 < оплачено < сумма.

### 0.4. Противоречие статуса и действия [Л]
- **Проблема:** сделка в статусе «Ждет оплаты» предлагает кнопку «Передать в сборку»; карточка снаружи показывает «Без склада», внутри склад (Матусевича) выбран.
- **Действия:** описать матрицу «статус → доступные действия»; кнопки перехода показывать только валидные для текущего статуса; синхронизировать отображение склада на карточке в воронке с данными внутри.
- **Критерии приёмки:** из каждого статуса доступны только логичные переходы; данные карточки в воронке и внутри модалки совпадают всегда.

### 0.5. Подтверждение удаления [Ф][U]
- **Проблема:** удаление вложения (иконка корзины) и удаление клиента/поставщика из списка — без подтверждения и без undo.
- **Действия:** диалог подтверждения для клиентов/поставщиков («Удалить клиента X? Связанные сделки сохранятся»); для вложений — подтверждение или undo-тост 5 секунд.
- **Критерии приёмки:** ни одно удаление не происходит в один клик без возможности отмены.

### 0.6. HTTPS
- **Проблема:** CRM работает по HTTP — логины, пароли, финансовые данные передаются открытым текстом.
- **Действия:** сертификат (Let's Encrypt), редирект HTTP→HTTPS, HSTS, cookie `Secure; HttpOnly; SameSite`.
- **Критерии приёмки:** все страницы по HTTPS; нет mixed content; старые HTTP-ссылки редиректят.

## Спринт 1. Воронка и карточка сделки (основной рабочий экран)

### 1.1. Автопривязка клиента по email [Л][Ф]
- **Проблема:** сделка, созданная импортом почты, имеет email отправителя, но клиент «— Не привязан —». Менеджер ищет клиента вручную.
- **Действия:** при импорте письма искать клиента по email в базе; если найден — привязать и показать подсказку «Привязан к клиенту X (по email)»; если нет — кнопка «Создать клиента» с предзаполненными email и названием организации из подписи письма.
- **Критерии приёмки:** для писем от известных клиентов привязка происходит автоматически; для новых — создание клиента из карточки в 2 клика.

### 1.2. История изменений [Ф]
- **Проблема:** логируется только создание карточки и импорт почты; изменения суммы, статуса, ответственного не фиксируются.
- **Действия:** лента событий в правой колонке: «ManagerY изменил сумму 4 000 → 5 176,45 BYN, 28.08 15:40», «Статус: Новый запрос → В работе», слитая с комментариями в единую хронологию (с фильтром «Комментарии / События / Всё»).
- **Критерии приёмки:** любое изменение ключевых полей видно в истории с автором и временем.

### 1.3. Связь суммы сделки и чек-листа [Л][Ф]
- **Проблема:** сумма сделки 5 176,45 BYN и суммы позиций чек-листа живут независимо; расхождение не видно.
- **Действия:** индикатор «Сумма позиций: X BYN из Y BYN сделки»; при расхождении — предупреждение. Привязка счёта к конкретной позиции чек-листа, а не общим списком.
- **Критерии приёмки:** расхождение сумм видно без вычислений в уме; у каждого счёта видна его позиция.

### 1.4. Заголовок-поле в карточке [Д][U]
- **Проблема:** название сделки — textarea, неотличимая от заголовка; можно стереть случайно.
- **Действия:** режим просмотра по умолчанию (H1 + иконка-карандаш), редактирование по клику на карандаш с подтверждением.
- **Критерии приёмки:** случайное изменение названия исключено; намеренное — в 2 клика.

### 1.5. Кнопка «Передать в сборку» [Д][Л]
- **Проблема:** огромная зелёная кнопка внизу — визуально главное действие карточки, но валидна не для всех статусов; рядом нет «Сохранить».
- **Действия:** блок переходов по статусам (см. 0.4) — компактные кнопки рядом с бейджем статуса в шапке; внизу оставить только если это основной следующий шаг для данного статуса.
- **Критерии приёмки:** главное действие карточки соответствует текущему статусу; недоступные переходы скрыты или disabled с тултипом-причиной.

### 1.6. Правая колонка и адаптив модалки [Д][U]
- **Проблема:** колонка «Комментарии» занимает ~50% ширины даже когда пустая; фон за модалкой скроллится; Esc не закрывает; нет возврата в предыдущий раздел.
- **Действия:** вкладки вместо постоянной двухколоночности («Данные / Комментарии (2) / Файлы») или сворачиваемая правая панель; блокировка скролла body; закрытие по Esc; URL карточки (`/deals/:id`) с возвратом туда, откуда открыли.
- **Критерии приёмки:** карточкой удобно пользоваться на 1366px; Esc и клик по фону закрывают; прямая ссылка на сделку открывается и делится.

### 1.7. Дедлайны [Л][Ф]
- **Проблема:** «Дата окончания» пустует, дедлайнов нет, просрочка нигде не индицируется (в списке воронки колонка «Дедлайн» вся «—»).
- **Действия:** дата окончания обязательна при переходе из «Новый запрос»; индикация на карточках воронки (красный бейдж «просрочено N дн», жёлтый «сегодня»); фильтр «Просроченные».
- **Критерии приёмки:** просроченные сделки видны на доске без открытия карточек; менеджер получает уведомление о дедлайне.

### 1.8. Масса «нулевых» сделок [Л]
- **Проблема:** 19 сделок «Новый запрос» с суммой 0,00 BYN, «Без склада», «Без ответственного» — письма-запросы, которые никто не разобрал. Колонка суммой 0,00 BYN.
- **Действия:** SLA-индикация («висит N часов без ответственного»), массовое назначение ответственного (выделение нескольких карточек), авто-назначение по правилам (круговое/по магазину).
- **Критерии приёмки:** ни одна сделка не висит без ответственного дольше заданного SLA без эскалации; массовое назначение ≤ 3 кликов.

## Спринт 2. Списки, финансы, справочники

### 2.1. Реестр оплат: горизонтальный скролл и обрезка [Д][U]
- **Проблема:** таблица финансов не влезает по ширине: «Примеча…», «Матусев…», «Богданов…», суммы обрезаны («17 427,51 В…»), дата «28.08.20…».
- **Действия:** пересмотреть ширины колонок (дата — фикс, название — резиновая с переносом, магазин — короткий код с тултипом); примечание — иконка с тултипом вместо колонки; sticky-заголовок и sticky-колонка «Название» при горизонтальном скролле.
- **Критерии приёмки:** на 1366px все данные читаются без скролла; суммы и даты не обрезаны никогда.

### 2.2. Странная арифметика в оплатах [Л]
- **Проблема:** у «Черутти» сумма сделки 1 275,31 BYN, а оплачено 56 645,00 — оплата в 44 раза больше сделки. Оплата, видимо, закрывает несколько сделок, но в реестре это выглядит как ошибка.
- **Действия:** поддержка «одна оплата → несколько сделок» с явным отображением («Оплата 56 645 распределена на 3 сделки»); предупреждение при вводе оплаты > суммы сделки.
- **Критерии приёмки:** переплата невозможна без подтверждения; распределённые оплаты читаемы в реестре.

### 2.3. Единообразие справочников [Д][U]
- **Проблема:** в «Клиентах» названия обычным текстом, в «Поставщиках» — жирным; в «Клиентах» есть иконки телефона/почты, в «Поставщиках» частично; разное поведение строк.
- **Действия:** единый компонент таблицы справочника: одинаковая типографика, иконки контактов, hover-строки, клик по строке = карточка (а не только карандаш).
- **Критерии приёмки:** «Клиенты» и «Поставщики» визуально и поведенчески идентичны.

### 2.4. Пустые карточки клиентов/поставщиков [Л]
- **Проблема:** у 8 из 22 поставщиков нет ни УНП, ни контактов, ни адреса — только название. У клиентов похожая картина.
- **Действия:** индикатор полноты карточки; при создании — обязательный минимум (название + хотя бы один контакт); автоподтягивание реквизитов по УНП (публичный реестр) — в перспективе.
- **Критерии приёмки:** новая карточка не создаётся пустой; у существующих виден статус «заполнена на N%».

### 2.5. CSV-экспорт и пагинация списка сделок [Ф][U]
- **Проблема:** список сделок — 25 на страницу, 12 страниц; нет выбора размера страницы; сортировки по колонкам нет (только фильтры); CSV выгружает непонятно что (текущий фильтр? всё?).
- **Действия:** сортировка кликом по заголовкам колонок; размер страницы 25/50/100; экспорт CSV = текущие фильтры + подтверждение «Выгрузить 286 сделок?».
- **Критерии приёмки:** любая колонка сортируется; экспорт соответствует видимому набору.

## Спринт 3. Задачи, календарь, дашборд

### 3.1. Раздел «Задачи» — глубина [Ф][Л]
- **Проблема:** задачи — три колонки и одна тестовая задача «Посидеть в тиктоке». Нет связи задачи со сделкой в обе стороны (в карточке сделки задач не видно), нет напоминаний, нет шаблонов («Перезвонить», «Выставить счёт»).
- **Действия:** блок «Задачи по сделке» в карточке; создание задачи из сделки одним кликом с автопривязкой; шаблоны задач; дедлайн → напоминание (колокольчик уже есть в шапке — связать).
- **Критерии приёмки:** из карточки сделки видны её задачи; создание задачи «перезвонить по сделке» ≤ 15 секунд; просрочка задачи видна в шапке.

### 3.2. Календарь [Д][Ф]
- **Проблема:** все события одного цвета (мятные), хотя легенда обещает три типа (Сделка/Оплата/Просрочено); клик по событию — непонятно что делает; длинные названия обрезаны; «ещё N» не раскрывается очевидно.
- **Действия:** реальная цветовая кодировка по типу события; клик → карточка сделки; «ещё N» → попап со списком дня; виды «Месяц/Неделя/День»; отображение дедлайнов и просрочек (см. 1.7).
- **Критерии приёмки:** тип события различим цветом; из календаря можно перейти в сделку; просроченное выделяется красным.

### 3.3. Дашборд → рабочий стол [Д][Л]
- **Проблема:** дашборд — статичная сводка «за все месяцы». Менеджеру нужно: «мои сделки требующие действия», «просрочки», «неоплаченные счета на этой неделе». «Без ответственного — 40 сделок на 24 016,55 BYN» похоронено в таблице топа менеджеров, хотя это тревожный сигнал.
- **Действия:** персональный режим дашборда (виджеты «Мои сделки по статусам», «Мои просрочки», «Ждут оплаты»); выделить «Без ответственного» в отдельный алерт-блок; период по умолчанию «этот месяц», а не «все».
- **Критерии приёмки:** менеджер, открыв дашборд утром, за 10 секунд понимает план на день; неназначенные сделки — красный алерт.

## Спринт 4. Общая дизайн-система и UI-опыт

### 4.1. Консистентность навигации и шапки [Д]
- **Проблема:** на разных разделах шапка перестраивается (на доске — свои контролы, в задачах — другие); заголовок «Воронка продаж (Канбан)» остаётся даже в режиме «Список»; кнопки-близнецы без подписей (две пары иконок рядом с «Доска/Список»); загадочная кнопка «1» рядом с заголовком на каждом разделе.
- **Действия:** убрать/подписать иконки без текста (тултипы); заголовок страницы = режиму («Воронка продаж — Список»); раскрыть назначение кнопки «1» или убрать; единый паттерн шапки раздела: заголовок слева, действия справа.
- **Критерии приёмки:** на каждой кнопке без текста есть тултип; заголовок отражает текущий режим.

### 4.2. Карточки воронки [Д][U]
- **Проблема:** на карточках много серого шума: «Без склада / Без ответственного / не заполнена» — три бейджа-пустышки на каждой карточке; «0,00 / 8 019,12 BYN» дублирует сумму.
- **Действия:** показывать бейджи-проблемы только когда это сигнал к действию («Нет ответственного» — красноватый, остальное скрыть); прогресс оплаты — тонкой полосой под суммой вместо дублирующей строки; «104 старых» — объяснить, что скрыто и почему.
- **Критерии приёмки:** карточка читается за 2 секунды: кто, сколько, что горит.

### 4.3. Ключевые операции с клавиатуры [U]
- **Действия:** Esc — закрыть модалку; Enter — отправить комментарий (Ctrl+Enter если многострочный); фокус в первое поле при открытии форм (в «Новой сделке» уже есть — распространить); Tab-порядок по формам.
- **Критерии приёмки:** создание сделки и добавление комментария возможны без мыши.

### 4.4. Скелетоны и состояния загрузки [U][Д]
- **Действия:** скелетоны для доски, списков, дашборда; единые empty-states («Нет сделок в этом статусе — перетащите сюда или создайте новую»); единые error-states с кнопкой «Повторить».
- **Критерии приёмки:** ни один экран не показывает белую пустоту при загрузке; каждая ошибка даёт действие.

### 4.5. Локализация интерфейса [Д]
- **Проблема:** смешение языков и стилей: «Webhooks», «воркфлоу», «Кастомные объекты», «Календарь» по-английски смещён (Пн начинается под средой — проверить сетку недели), «Выполнены» вместо «Выполненные».
- **Действия:** словарь интерфейса, вычитка; проверка календарной сетки (первый день недели, соответствие чисел колонкам).
- **Критерии приёмки:** интерфейс полностью на русском; календарь показывает верные дни недели.

### 4.6. Тёмная тема [Д]
- В сайдбаре уже есть иконка темы — проверить, довести до конца все разделы (модалки, таблицы, бейджи), запоминать выбор.
- **Критерии приёмки:** тёмная тема покрывает 100% экранов без «белых пятен».

## Спринт 5. Настройки, права, интеграции

### 5.1. Админ-панель: разграничение доступа [Л][Ф]
- **Проблема:** ссылка «Админ-панель» видна в сайдбаре у менеджера (ведёт на отдельный логин — хорошо, что отдельная сессия; плохо, что видна всем).
- **Действия:** показывать пункт только роли admin; аудит входов; 2FA для админов; журнал действий администратора.
- **Критерии приёмки:** менеджер не видит вход в админку; все действия админа логируются.

### 5.2. Роли и видимость сделок [Л]
- **Действия:** роли: менеджер (свои сделки + неназначенные), руководитель (все), бухгалтер (финансы read/write, сделки read). Фильтр «Мои сделки» по умолчанию для менеджера.
- **Критерии приёмки:** менеджер по умолчанию видит свою воронку; руководитель переключается на любого менеджера.

### 5.3. Импорт почты: качество парсинга [Ф]
- **Проблема:** сделки из писем создаются с темой «Письмо: Запрос», «Письмо: заявка» — неинформативно; тело письма свёрнуто («показать полностью»), спецификация не структурирована.
- **Действия:** извлечение названия организации из подписи/домена → в название сделки («Запрос — АтомГрупп»); парсинг табличной спецификации из тела письма в черновик позиций; фильтр рассылок/спама (письмо от mvd.gov.by «может вас заинтересует» — не сделка).
- **Критерии приёмки:** 80% сделок из почты имеют осмысленное название без ручной правки; спам не попадает в воронку.

## Регрессионный чек-лист после каждого спринта

1. Вход → доска: карточки грузятся, суммы колонок корректны, «старые» раскрываются.
2. Открыть сделку → изменить сумму/дату/клиента → индикатор сохранения → F5 → данные на месте.
3. Сделка из письма: клиент привязан/предложен к созданию; комментарий с письмом разворачивается.
4. Чек-лист: отметить «Оплачен поставщику»/«Пришло» → прогресс и «Осталось оплатить» пересчитались; статус оплаты клиента корректен.
5. Переходы статусов: доступны только валидные действия; «Передать в сборку» — когда положено.
6. Финансы: реестр без обрезанных колонок; оплата > суммы сделки — предупреждение.
7. Задача из сделки → видна в обоих местах → дедлайн → напоминание.
8. Календарь: типы события различимы цветом, клик открывает сделку.
9. Удаление клиента/файла — с подтверждением/undo.
10. Всё вышеперечисленное — с клавиатуры (Tab/Esc/Enter) и в тёмной теме.
