## 2. Производительность (прод-объём)

- Вес после входа: DOM **20 843** узла, из них скрытый `#view-fin` — **14 839 (71 %)**;
  `#kb-board` 3 814; SVG 641 (в доске 567); плиток `.kb-card` 189 из 383 активных
  (закрытые не рисуются); строк фин-таблиц 592; JS-куча 3.8–5.2 МБ; передано
  **5 627 КБ** (60 ресурсов), `/kanban/cards` 474 КБ за 96 мс; первая карточка 277 мс.
- Одно действие = полный перерендер доски (`renderBoard()` = `innerHTML=''` + сборка,
  `shell-v2-board.js:180-199`): 1 символ поиска (debounce 150 мс) → рендер ≈ 48.8 мс;
  одна галочка «Заказано» → **long task 60–69 мс** + `PATCH /checklists/{id}`;
  открытие/закрытие карточки → 0 мутаций доски; drag&drop → 22 мутации, long tasks 0.
- **Long tasks >200 мс: 0** во всех трейсах (покой 15 с, действия 10 с, 60 с, 10 мин).
- Запросы сами по себе: 60 с простоя = 1 (`GET /notifications`); 10 мин = 10 (1/мин).
  Поллинга канбана/финансов нет.
- Накопление: 3 круга по 7 разделам → DOM +5, куча −0.2 МБ; 30 циклов
  «карточка→Закупка→галочка→Esc→раздел→доска» → куча осциллирует 2.7–5.6 МБ (GC),
  DOM константа 21 185, RSS дерева 424→591 МБ к 30-му циклу → 521 МБ после покоя.

  за 1–2 мин, ни за 10 мин простоя. Единственная неограниченная деградация сборки —
  петля дровера клиента (F1). Постоянная цена вкладки (объясняет «145 МБ»):

## 4. Поправки к прежним гипотезам (важно, чтобы не чинить дважды)

1. **CSP-ошибки — не «Закупка».** В дровере карточки нет ни одного `<img>`: файл счёта
   показывается ссылкой, скачивание идёт через `href="blob:…"` (CSP его не режет).
   Все 14 ошибок — миниатюры входящих накладных в скрытом `#view-fin` (F2).
   Визуального превью файла в закупке нет вообще — это UX-пробел, а не CSP-блокировка.
2. **Esc закрывает дровер карточки** (`showModal()` + обработчик `cancel`, ~202 мс
   с анимацией выхода); прежний замер «не закрылся» — артефакт сценария
   (ожидание без учёта 120 мс exit-анимации). Доказательство: `toolout/c1c2c3.txt` (C3).
3. **Зависание на доске не воспроизведено** ни в одном замере; подтверждённый
   «вечный» механизм один — F1 (Клиенты).

## 9. 24.09 — As-built после полного прохода v2

Этот раздел описывает фактический прогон на локальном стенде `8125` с копией БД и
авторизованной sandbox-учёткой. Production, production-БД и legacy не затрагивались.

### Исправленные и подтверждённые пункты

- primary-кнопки в management/admin/dialog-контекстах сохраняют accent-семантику;
  dark primary использует `var(--accent-ink)`, без hardcoded белого;
- «Чья очередь» и «Новая задача» используют общий `.v2-form-dialog` shell;
- финансовые таблицы используют фиксированную геометрию, ограниченные details и
  внутренний горизонтальный scroll — page-level overflow не появляется;
- три финансовых поиска имеют по одному плоскому input/крестику, `inert` в закрытом
  состоянии, Escape и возврат фокуса;
- финвкладки в тёмной теме получили accent-фон. Подтверждено в браузере после
  пересборки: `background: rgb(142, 138, 245)`, `color: rgb(20, 22, 26)`,
  `box-shadow: none`;
- board search не даёт синего прямоугольного focus в light/dark;
- редактирование даты оплаты — нативная кнопка с accessible name, открытие date
  input и возврат кнопки проверены;
- открытие финансовой строки — нативная кнопка с `data-card-open`, pointer и
  Enter/Space используют общий bridge и открывают drawer;
- combo имеет `combobox/listbox/option`, `aria-activedescendant`, стрелки, Home/End,
  Enter, Escape и свободный текст.

### Проверки и результаты

- `bash scripts/check.sh` — exit 0: `897 passed`, JS syntax, data-handler heuristic,
  свежесть `site-v2`, версии статики — зелёные.
- `v2_design_matrix.py` на ширинах 1920/1440/1280/1024/768/430/375 и light/dark —
  102 скриншота, 0 page overflow и 0 overlaps. Сокращения длинных названий и
  контактов отмечены отдельно; прозрачный текст checkbox-кнопки дал false-positive
  contrast и не является видимым текстом.
- Ручная браузерная матрица на 8125: все маршруты `#day`, `#board`, `#tasks`,
  `#fin`, `#clients`, `#suppliers`, `#admin` открылись в обеих темах; overflow на
  375–1440 = 0; finance search, date editor, finance open button, combo, Escape,
  focus и dark pressed-state подтверждены.
- `v2_functional_audit.py` на локальной копии: PASS для входа, поиска, очередей,
  сводки 553 и первого шага тестовой сделки; на шаге проверки строки реестра
  скрипт остановился с timeout после создания локальной тестовой сделки 1029.
  Одновременно скрипт сообщил 170 рассинхронизаций `stage`/API в этой копии БД.
  Это ограничение fixture/аудита, не подтверждённый регресс текущего v2; cleanup
