# Спека пункта 13 — «Паритет-пакет 1: виды и фильтры доски» (23.09.2026)

Формулировка в журнале: `docs/audits/V2-WORKPLAN-2026-09-22.md`, пункт 13. Референс
паритета — замороженный legacy `site/js/kanban.js` (только чтение). Спека
самодостаточна; факты сверены с кодом 23.09.

## 0. Контекст и решения

- **«Список»** — табличный вид всех не-удалённых сделок (паритет
  `renderListView()`, `kanban.js:1058-1227`): просроченные наверх, далее по дате
  создания (новые сверху), клиентская пагинация по 25 строк (`LIST_PAGE_SIZE=25`,
  `kanban.js:1055`).
- **«Архив»** — те же строки таблицы, но только сделки со статусом «Закрыто»
  (клиентский `stage === 'done'`; сервер возвращает закрытые в
  `GET /kanban/cards`, фильтра по статусу там нет — `kanban_router.py:72`).
  Архив — **живой фильтр над `KBData.cards`, не снимок**: отмена ТН возвращает
  карточки из «Закрыто» в «На списание»/«Сборку» (`services/payments.py:114-130,
  269-272`), после `reloadData` карточка обязана исчезнуть из архива. Никакого
  кэширования состава архива. Сознательное пересечение с очередью «Списано»
  (она показывает `done` + полностью выписанные без смены статуса,
  `board.js:984-988`) — документировано в журнале: «Списано» — операционная
  очередь выписки, «Архив» — реестр закрытых сделок.
- **Фильтр «Тип оплаты»**. Отдельного поля оплаты у Card НЕТ; в legacy
  «Безнал (БН)» — псевдо-магазин: `APP_STORES`, `site/js/constants.js:12-16`,
  комментарий: «„БН" (безнал) — способ оплаты, а не физическая точка». В v2
  клиентский фильтр по сырому `store_location`: `bn` = `storeRaw === 'БН'`,
  `cash` = `storeRaw !== '' && storeRaw !== 'БН'`. Карточки без магазина
  (`storeRaw === ''`) не попадают ни в один из двух — как в legacy, где NULL
  не matching ни одной конкретной опции (на копии прод-БД таких 48 из 391
  активных; карточек с «БН» на копии 0, справочник магазинов «БН» не содержит —
  `/tmp/v2-audit-prod/crm_app.db`, `store_locations`: Матусевича, Богдановича).
- **Фильтр «Приоритет»**. `cards.priority` — int 0..3 (`models.py:132`),
  сервер отдаёт в `CardResponse` (`schemas.py:258`), клиент в маппинге терял.
  Опции фильтра — `NC_PRIORITY` (`board.js:3033`: 0 «Без приоритета», 1
  «Низкий», 2 «Средний», 3 «Высокий») + «Все приоритеты». Отступление от legacy
  (там фильтр без «0», `index.html:141-146`): на проде все 391 активных карточек
  имеют priority 0, без опции «Без приоритета» фильтр всегда пуст — документировать
  в журнале.
- **«Сбросить»** — кнопка в тулбаре (паритет `resetKanbanFilters`,
  `kanban.js:1014-1026`): очищает поиск, магазин, приоритет, тип оплаты. Режим
  не трогает. Существующая `resetBoardFilters()` (`board.js:789-804`) и кнопка
  в подсказке `#kb-reset-filters` (`prototype.html:793`) расширяются теми же
  фильтрами; тулбарная кнопка — отдельный id.
- **Сохранённые виды** (спецификация из пункта 15, серверных роутов нет):
  localStorage, ключ `v2.savedViews.board.<userId>`, `userId` из
  `V2Api.userId()` (`v2-api-template.js:70`; null до `/auth/me` и в демо —
  тогда суффикс `'anon'`). Состав вида — `{id, name, q, store, statuses[],
  assignee, mode}` + **аддитивное расширение `priority`, `pay`** (иначе вид не
  может зафиксировать новые фильтры; отступление от буквы спеки п.15
  документируется в журнале). `statuses` хранить как `[]`, `assignee` как
  `null` — задел, UI к ним в этом пункте нет, при применении игнорируются.
  `mode` сохраняется только из `board|list|archive` (очередные режимы
  сохраняются как `board`). Применение — выставить состояние и записать адрес
  через `writeBoardParams` (формат, который доска парсит). Событие
  `kb:saved-view-applied` (CustomEvent, `detail: {id, name}`). Тихая потеря
  несуществующих фильтров: при применении вида и по `kb:dictionaries-changed`
  магазин, которого нет в справочнике, молча сбрасывается в `all`. Весь доступ
  к localStorage — в `try/catch` с молчаливой деградацией (`file://`).
