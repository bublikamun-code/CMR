## Пересечения с пунктом 13 (обязательны к части B)

После Р2 каноническое «Закрыто» получает id `closed`, `done` остаётся
псевдо-этапом полной выписки. Код пункта 13 в `board.js` классифицируется так:

- `board.js:1305` — фильтр режима «Архив» `c.stage === 'done'` →
  **`c.stage === 'closed'`** (архив — по статусу сделки), комментарий над
  `listCards()` (`:1291-1294`) поправить соответственно.
- `board.js:1296` — `LIST_STAGE_FALLBACK`: `'done'` → `'Списано'`, добавить
  `'closed': 'Закрыто'` (псевдо-done карточка — статус «На списание» с нулевым
  остатком; в колонке «Статус» таблицы для неё честно писать «Списано»).
- `board.js:1226` — фильтр очереди «Списано» (Р2): добавить `closed`:
  `c.stage === 'done' || c.stage === 'closed' || (c.stage === 'writeoff' && …)`
  — закрытые сделки остаются в «Списано», как сейчас.
- `board.js:302` — `card.stage = 'done'` после групповой выписки: сервер ставит
  карточкам статус «Закрыто» (`writeoff_groups_router.py:218-219`) → **`'closed'`**.

## Часть B — `tools/mockups/shell-v2-board.js` (актуальные якоря)

Классификация `done`/`closed` (правило спеки §2; каждое место сверить по
контексту):

- остаются **`done`** (факт полной выписки, readonly-гварды): `:1496`, `:1584`,
  `:1611`, `:1624`, `:1820`, `:1835`, `:2886` (текст подсказки), `:2912-2917`
  (псевдо-этап после полной выписки), `:3017`, `:3047`, `:3175`, `:3261`,
  `:2459`/`:2468` (псевдо-«Списано» в селекте этапов для выписанной карточки).
- → **`closed`**: `:302` (после групповой выписки — сервер ставит «Закрыто»),
  плюс три пункта из блока «Пересечения с пунктом 13» выше.

Селект «Этап» дровера (`:2459-2468`): для закрытой карточки (`c.stage ===
'closed'`) в списке этапов сейчас нет опции — регрессия. Добавить псевдо-опцию
`{ id: 'closed', name: 'Закрыто' }` с тем же условием показа, что у `done`
(`(st.id !== 'closed' || c.stage === 'closed')`), disabled для закрытых, как
`done` для выписанных. Дубль id после Р2 исчезает сам — псевдо-опции `done` и
`closed` сосуществуют легально (цель «убрать дубль `:1289`» достигнута Р2).

Р4 — `canAssign` в двух местах (тост точно «Статус не из справочника карточек:
сервер его не примет», стиль ошибки):

1. `boardEl.addEventListener('drop', …)` (`:647`): после `var toStage = …`, до
   `moveCard`: найти статус `KBData.statuses` по `id === toStage`; если найден и
   `canAssign === false` — тост, `cleanupDrag()`, выход без мутаций DOM и
   запроса. Перестановка внутри недоступной колонки тоже запрещена (этап не
   меняется, но карточка в ней жить не может).
2. Обработчик смены этапа в дровере (`:3281`, ветка `key === 'stage'`): сейчас
   `if (activeCard.stage === 'done' || !KBData.statuses.some(…)) return;` —
   добавить в guard `activeCard.stage === 'closed'` (закрытая карточка
   readonly) и проверку `canAssign === false` найденного статуса с тем же
   тостом (опции селекта уже отфильтрованы — это защита от прямого пути).

## Часть D — `tools/mockups/shell-v2-management.js` (актуальные якоря)

- `:83` — статусы админки берутся из `KBData.statuses`, а boot фильтрует
  неактивных (`v2-boot-template.js:126`) → выключенный статус исчезает из
  админки и его не включить обратно. Источник данных раздела — прямой
  `GET /dictionaries/statuses` (роут возвращает все строки, включая
  неактивных): загрузить при открытии раздела, перечитывать после сохранения.
  Записи привести к совместимому с `persist()` виду (`serverId` = числовой id).
- `:91` дескрипторы формы статуса (`name/color/position`):
  - Р3: `name` для канонического статуса — только чтение с подсказкой.
    Канон — тот же список, что `CANON_ID` в boot (`schemas.CARD_STATUSES`):
    «Новый запрос», «В работе», «Ждет оплаты», «Сборка», «На списание»,
    «Закрыто». Подсказка (по-русски): имя канонического менять нельзя — сделки
    хранят статус именем, сервер принимает только канонические имена (422),
    переименование оставило бы карточки без колонки. Неканоническое имя
    правится как раньше (критерий 5 спеки).
  - Р5: добавить `is_active` (чекбокс, по умолчанию включён для нового).
    Сохранение — через существующий `status-save` (boot `:736-740` отдаёт
    `fields` в PATCH как есть): имя канона в `fields` не отправлять,
    `is_active` — отправлять. После сохранения перечитать список из API и
    рассылать `kb:dictionaries-changed` как сейчас (`:206`).
  - Таблица (`:139`): показать «Отключён» для `is_active === false`; роль
    выводить честно по правилу Р1 из имени (writeoff → «Очередь списания»,
    archive → «Архив», иначе «Колонка доски») — у прямых ответов API поля
    role нет, выводится тем же правилом, что в boot, с комментарием-ссылкой.
