# Правила работы в этом проекте

## Скоуп

Только веб-приложения. В разработке три проекта: **СРМ** (этот репозиторий),
**Сайт** и **второй сайт** (вне этого репозитория). Ничего вне веб-приложений
не делаем: девопс-скрипты, утилиты, смежный код — вне скоупа, если пользователь
явно не попросил обратное.

Этот проект — CRM: бэкенд на FastAPI/Python (`routers/`, `services/`,
`database.py`, `models.py`), фронтенд — чистые JS/CSS без сборщика (`js/`,
`css/`, `admin.html`), БД SQLite + миграции в `migrations/`. Проверка
изменений — `pytest` (тесты в `tests/`), финальный прогон тестов всегда
делает главный агент.

## Оркестрация: делегирование субагентам

Главный агент (K3) планирует и координирует, а конкретные подзадачи делегирует
субагентам, выбирая модель из пула по сложности задачи:

| Модель | Когда использовать |
| --- | --- |
| `kimi-code/kimi-for-coding-highspeed` (default) | Простые подзадачи: поиск по коду, чтение файлов, мелкие правки на несколько строк, короткие сводки, рутинные изменения без ветвлений логики |
| `kimi-code/kimi-for-coding` | Средние и сложные подзадачи: изменение нескольких файлов, рефакторинг, исправление багов с нетривиальной логикой, новые эндпоинты |
| `kimi-code/k3` | Очень сложные подзадачи: многошаговые архитектурные изменения, дебаг нестабильных/редких багов, комплексный анализ целой подсистемы |
| `k3-max` | Самые тяжёлые подзадачи: глубокий дебаг, системный дизайн, случаи, где K3 на high effort не справилась |

Правила:

- Не делегировать тривиальные задачи, которые дешевле сделать самому
  (прочитать известный файл, внести точечную правку).
- Независимые подзадачи одного типа запускать параллельно через `AgentSwarm`,
  с явным выбором модели в параметре `model`.
- Большая реализация: сначала `plan`-субагент или `explore` на высокоскоростной
  модели для разведки, затем `coder` на модели, соответствующей сложности.
- Если субагент не справился или его результат вызывает сомнения —
  резюмировать его же (`resume`) или перезапустить задачу на модели уровнем выше,
  а не пытаться «додумать» за него в главном контексте.
- Финальную сборку, проверку тестов и отчёт пользователю всегда делает
  главный агент сам.
