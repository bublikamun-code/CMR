# Макеты (чистый HTML, вне прода)

Здесь лежат HTML-макеты для согласования визуала **до** правок боевого `css/` и `index.html`.
Ничего из этой папки не деплоится. Прототип проверяется отдельными браузерными
сценариями в `tools/visual-check`, без подключения к backend.

## shell-v2-prototype.html — прототип радикальной переработки UI

Открыть в браузере (интернет нужен только для шрифта Manrope, без него — системный):

```bash
open tools/mockups/shell-v2-prototype.html
```

### Демо-«сервер» (shell-v2-data.js)

Справочники и карточки живут в одном модуле — по структуре как на проде:
`statuses` (deal_statuses: id, название, цвет, позиция, роль «колонка доски /
очередь списания»), `stores` (store_locations), `users` (одна таблица и для
админки, и для ответственных), `clients` и `suppliers` (сущности с ID и
реквизитами), `cards` (сделки). 60 детерминированных демокарточек (тот же
PRNG-сид, что раньше) плюс отдельный поток PRNG для сумм оплат, чтобы раскладка
доски не менялась. Демо-дата «сегодня» — 12.09.2026, согласована с календарём
задач. Доска, пульт дня, «Клиент 360» и админка читают один и тот же набор;
правки админки расходятся по экранам через событие `kb:dictionaries-changed`.
Всё по-прежнему только до перезагрузки.

### Навигация и адаптивная оболочка

Открывается **Доска сделок** (`#board`), а не галерея. Один рельс навигации
работает на всех ширинах: слева на десктопе, горизонтальная прокручиваемая
полоса с подписями сверху при ≤720 px. На телефоне это настоящая рабочая область,
без рамки телефона и дублирующих меню. Все разделы и тема доступны касанием и Tab.
Полоса занимает место в раскладке и не перекрывает доску.

| Адрес | Содержимое |
| --- | --- |
| `#board` | Доска сделок, очереди «На списание / Списано» |
| `#day` | Пульт дня: KPI и очередь внимания |
| `#clients` | Клиенты: таблица и карточка клиента |
| `#fin` | Финансы: реестр, документы и входящие |
| `#tasks` | Задачи, сводка и календарь — один экран |

Календарь — часть экрана «Задачи» (ниже списка), отдельного пункта меню нет;
старый адрес `#calendar` работает как алиас `#tasks`.

Hash, заголовок страницы и раздела, активный пункт и `aria-current="page"`
синхронизируются при кликах, прямом открытии, reload, назад/вперёд.
Пустой или неизвестный hash (включая старые `#kit` / `#mob`) заменяется на `#board`
без добавления лишнего шага истории. Галерея компонентов, телефонный макет,
фиктивные уведомления, пользователь и палитра действий удалены из оболочки.
Есть ссылка «К содержимому» для клавиатуры. Тема меняется локально, без хранения.

**Поставщики / Админ-панель** доступны по `#suppliers` / `#admin`.
Поставщики: поиск, создание и редактирование; тот же каталог используется
в пунктах закупки. Удаление не реализовано, ссылки на поставщиков сохраняются.
Админка: локальное создание/редактирование логинов (плюс полное имя), магазинов
и статусов. Это не создание реальных аккаунтов и не изменение серверных прав.
**Правки пользователей, магазинов и статусов сейчас же меняют доску** —
названия и порядок колонок, цвет полосы колонки, фильтр магазинов, списки
ответственных, чипы карточек, пульт дня и «Клиент 360» (событие
`kb:dictionaries-changed`). Новые статусы получают роль «колонка доски»;
поле «Назначение» в таблице показывает роль. Цвет можно задать как hex
(пипетка), колонка подхватит его в обеих темах. Изменения живут до перезагрузки.
Рабочая CRM и `/admin` не заменены этим предпросмотром.
Проверка: `node tools/visual-check/management-verify.mjs`.

**Ограничения:** индикатор «Предпросмотр · данные не подключены» остаётся в шапке.
Бизнес-действия пульта, клиентов и задач по-прежнему визуальные образцы;
рабочая навигация не означает подключения этих действий к backend.
Финансы и канбан сохраняют существующие локальные взаимодействия.

Проверка (существующий `playwright-core` + установленный Chrome, без backend):

```bash
cd tools/visual-check
node navigation-verify.mjs
node kb-verify.mjs
node kb-interactions.mjs
node payment-menu-verify.mjs
```

Новый тест проверяет 1440 / 375 / 430 px, все шесть адресов в обеих темах,
прямые ссылки, историю, reload, неверный hash, уникальные `[data-view]`, клавиатуру,
недоступные пункты, отсутствие горизонтального переполнения страницы и ошибок JS.
`[data-view="board"]` остаётся единственным селектором на любой ширине.
Нижняя граница доски — **888 px при viewport 900 px**, как прежде;
верхняя граница изменилась из-за удаления галереи и мобильной полосы.
Скриншоты нового теста: `/tmp/navigation-{1440,375,430}.png`.


### Канбан: плотность и очередь выписки

- Реализация изолирована в `shell-v2-board.css` и `shell-v2-board.js` рядом с HTML.
- 60 детерминированных демокарточек распределены между четырьмя колонками и очередью.
  Переключатель «Доска / На списание / Списано» меняет рабочую область: пятой колонки
  и дублирующей очереди снизу нет. Панель карточки открывается поверх доски.
  Колонки прокручиваются вертикально независимо, на узком экране вся доска —
  горизонтально внутри своей области. Карточки переносятся мышью между колонками
  и внутри колонки; во время переноса видно место вставки. Поиск и магазин
  применяются также к очереди.
- SVG-кнопка плотности переключает «Компактно / Обычно»: меняет отступы и видимость
  ответственного, а не масштаб браузера. SVG-кнопка поиска раскрывает поле с анимацией
  и переводит в него фокус; Escape закрывает поиск и сбрасывает запрос.
- Карточка открывается в боковой панели поверх доски: суммы, этапы, данные сделки,
  закупка, накладные и история. «Условия оплаты» (`paymentTerms`)
  и этап редактируются в шапке панели. Галочка «Оплачено» убрана; данные платежей не меняются. Условия:
  «Не выбраны» (`''`), «Отсрочка» (`deferred`), «Оплата 100%» (`full`),
  «Частичная оплата + отсрочка платежа» (`partial_deferred`). Выбор не отмечает оплату.
  Во вкладке «Обзор» кнопка «Скрыть заполненные поля / Показать все поля» управляет
  только полями обзора, не шапкой. По умолчанию показаны все поля; предпочтение общее
  для карточек, хранится в памяти до перезагрузки. Скрытие пересчитывается только
  по кнопке или при повторном открытии карточки — не при вводе, потере фокуса,
  смене вкладки или обновлении суммы. Пустые и невалидные поля остаются видимыми;
  допустимое значение `0` (например, индекс менеджера) считается заполненным.
  Когда скрыты все поля, подсказка предлагает показать их снова. После обновления
  суммы фокус сохраняется на её поле. Hover/focus полей панели нейтральные в обеих
  темах (`--muted`, токены границ); клавиатурная обводка и индикация ошибок сохранены.
  Закупка:
  Каждый пункт имеет собственный выбор поставщика (`supplier_id`) и один файл.
  Файл можно скачать, заменить или открепить; другие пункты не меняются.
  Справочник поставщиков демонстрационный. Файлы — локальные `File`/object URL,
  только до перезагрузки; сеть и рабочая база не используются. Лимит 25 МБ,
  расширения совпадают с backend; проверка содержимого остаётся задачей backend
  при интеграции. Замена/открепление освобождают прежний object URL.
  Проверка: `node tools/visual-check/procurement-verify.mjs` (375/430/1440, обе темы).
  «Заказано / Получено», получение доступно после заказа; счётчики на карточке
  сохраняются при каждом обновлении доски. «В списание» переводит карточку из сборки в представление «На списание».
  В демо незавершённый чек-лист не блокирует этот переход; правило требует согласования.
- Выписка: дата, серия, номер, сумма в целых копейках. Нулевая/слишком большая сумма
  и повтор серии+номера в одной карточке запрещены. Частичная выписка сохраняет
  остаток в очереди «На списание»; полная переносит карточку в представление «Списано».
  Там доступны карточка и все выписанные накладные. Это не удаление данных.
- Отмена ТН: кнопка «Отменить» у каждой выписанной накладной (двухшаговое
  подтверждение). Как на проде, удаление документа возвращает остаток: сумма
  снова в «Осталось выписать», строка исчезает из «Финансы → Документы»,
  карточка, закрытая полной выпиской, возвращается в очередь «На списание».
- Групповая выписка (2+ карточек → одна накладная): в очереди «На списание»
  у карточек появились чекбоксы («Выбрать все» в шапке панели). Кнопка
  «Накладная на группу (N)» открывает диалог: список карточек с остатками,
  общий клиент/магазин («Разные клиенты», если неодинаково), итоговая сумма,
  дата/серия/номер (дубль номера в группах запрещён). После выписки каждая
  карточка закрыта своим покрытием (`groupId` + covers), уходит в «Списано»,
  на доске помечена «групповая ТН», во вкладке «Накладные» видна запись
  группы с кнопкой отмены. Отмена групповой ТН возвращает остаток КАЖДОЙ
  карточке и возвращает их в очередь. Группа появляется в «Финансы →
  Документы» (чекбокс «ТН у нас») и в «Журнале выписки» со списком
  связанных карточек — это аналог `writeoff_groups` прод-модели.
- Оплата по модели карточки (total_amount / paid_amount): поле «Оплачено»
  в шапке карточки и чип «оплачено …» / «оплачено полностью» на доске; суммы
  в тех же целых копейках, отдельный PRNG-поток. Условия оплаты (`paymentTerms`)
  остаются демо-полем: в модели карточки его нет, при интеграции нужна
  отдельная согласованная миграция, а не запись условия в `payment_status`.
  Выбор условий оплату не отмечает.
- **Ограничения:** демо-данные общие (доска, пульт, клиенты, админка), но
  статичный реестр «Финансов» и журнал — отдельные образцы; выписанные ТН
  попадают в «Финансы → Документы» только на время демосессии, отметки «ТН у нас»
  и «Оригинал ТН возвращён» синхронизированы в обе стороны. Нет бэкенда, реальной
  оплаты, групповой выписки и подключения справочников к API.
  Чек-лист показывает позиции, не полноценную базу поставщиков. Изменения
  исчезают при перезагрузке. Это предложение интерфейса, не подтверждение
  паритета с боевой CRM.
- Браузерные сценарии для Chrome (`tools/visual-check/`): `node kb-verify.mjs` —
  валидация суммы, частичная/полная выписка, дубль, история, ширины 375–1920 px
  в обеих темах; `node kb-interactions.mjs` — перенос мышью в точную позицию,
  перестановка в колонке, счётчики, варианты и сохранение условий оплаты независимо
  от статуса платежей, отсутствие галочки «Оплачено», скрытие/показ полей, пустая заметка, восстановление всех полей,
  отсутствие исчезновения при редактировании, фокус после обновления суммы,
  нейтральный hover и клавиатурный focus input/select/textarea в обеих темах,
  связка ТН с финансовыми документами, внутренняя прокрутка колонок и очереди.
  Проверки пройдены главным агентом в Chrome.
  Все четыре колонки помещаются по ширине на проверенных десктопных размерах при 100%.
  Общие стили доски — `shell-v2-controls.css`; панель карточки — `shell-v2-card.css`.
  Реальный браузерный zoom 75% отдельно не проверялся.

### Общие меню и детали оплаты

- `shell-v2-select.js/css`: все select панели и фильтр магазина используют один
  компонент. Нативный select остаётся для значения и событий, но скрыт после
  enhancement. Тот же trigger — первая строка раскрытой общей поверхности без
  второй рамки. Меню выходит в top layer, список прокручивается; стрелки,
  Home/End, Enter/Space, поиск по первой букве, Escape и Tab поддержаны.
  Hover и фокус нейтральные; touch-target при coarse pointer — минимум 44 px.
- `shell-v2-payment.js/css`: выбор условий сразу раскрывает «Обзор» и показывает
  блок оплаты в начале прокручиваемой области, без ручной галочки «Оплачено».
  «Скрыть заполненные поля» не затрагивает этот блок.
- Отсрочка: конечная дата **или** 1–36500 календарных дней после даты начала.
  Начало по умолчанию — местный сегодняшний день; расчёт календарный, без UTC-сдвига
  и ошибки на DST. Частичная оплата дополнительно требует предоплату >0 и <суммы
  сделки, максимум два десятичных знака; сохранение — в целых копейках.
- Валидный нормализованный снимок находится в `card.paymentDetails`. Сырые черновики
  отдельно в WeakMap: неверный ввод не перезаписывает предыдущий валидный снимок,
  видна ошибка «Не сохранено». Выбранные условия находятся в `card.paymentTerms`;
  предыдущий снимок может относиться к прежним условиям, пока новые невалидны.
  Переключение условий/способа и повторное открытие сохраняют черновик каждой карточки.
  Уменьшение суммы, конфликтующее с сохранённой предоплатой, сбрасывает снимок;
  введённая предоплата остаётся с ошибкой, не обрезается автоматически.
- `payment-menu-verify.mjs` проверяет даты/дни, високосный год, DST, две часовые зоны,
  копейки, неверные черновики и снимки, переключения/карточки, независимость оплаты,
  фильтр обзора, изменение суммы, клавиатуру, размеры 375/430/1280/1440/1920,
  обе темы, единую поверхность, clipping и отсутствие ошибок JS.
  Выбор в тестах идёт через видимое меню (`kb-select-helper.mjs`), не `selectOption`.
  Проверен Chrome с мобильной эмуляцией, не физические устройства и не Safari/Firefox.
  Всё живёт только до перезагрузки; реальных платежей и backend-сохранения нет.


### Пульт дня и «Клиент 360» (shell-v2-insights.js)

Оба экрана считаются из тех же демо-данных, что и доска, и обновляются при
каждой её перерисовке (`kb:documents`) и после правок админки.

- **Пульт дня.** KPI: «Сделки в работе» — активные карточки; «Сумма воронки» —
  их сумма; «Оплачено по сделкам» — сумма `paid_amount` активных; «Просрочено» —
  сделки с долгом и истёкшим сроком из числа должников. Выдуманные дельты
  «к августу» убраны: в демо-данных нет истории, честнее не показывать.
  Очередь «Требует внимания»: просроченные оплаты (красные, кнопка «Оплата»),
  сроки в ближайшие 3 дня (жёлтые), готовые сборки (зелёные). Все кнопки
  «Открыть/Оплата/Отгрузить» переключают на доску и открывают конкретную
  карточку (`KBBoard.open`). Топ клиентов и «Дедлайны на неделе» считаются по
  активным сделкам. Под «Воронкой · сентябрь» (тёмная карточка: активные
  сделки и суммы по магазинам, вместо бывшей статичной теплокарты) —
  «Ближайшие отгрузки» из «Сборки»; третья карточка — «Списано и очередь»:
  живое состояние выписки (к выписке, списано за сессию, групповые и обычные
  ТН). Декоративной осталась только сетка-heatmap в тёмной карточке.
- **Задачи.** Список рендерится из демо-набора задач в `shell-v2-data.js`
  (исполнитель — из справочника пользователей, группировка «Просрочено /
  Сегодня и завтра / На неделе / Выполнено» — по демо-дате 12.09.2026).
  Справа — сводка: открытые задачи по исполнителям и срез по срокам.
  Создание и отметка задач в превью не работают — кнопки помечены.
- **Клиенты.** Таблица рендерится из справочника `clients` (сущности с ID,
  УНП, контактами), поиск фильтрует по названию/УНП/контакту/телефону. Клик
  по строке (или Enter с клавиатуры) открывает «Клиент 360»: реквизиты,
  KPI (сделки/оплачено/просрочено), список его сделок со статусами и суммами,
  отдельные строки просроченных оплат; кнопка «Открыть» у сделки переключает
  на доску и открывает карточку. Вкладки оплат/накладных/задач клиента
  и кнопки «Новая сделка/Позвонить/Печать» — образцы, честно помечены.

### Финансы: работающие сценарии и границы

- Три обычные кнопки с `aria-pressed` переключают **Реестр оплат**, **Документы**
  и **Входящие накладные**; без `role=tab`, линейного пути и каскадов статусов.
- Реестр содержит четыре карточки: дата записи, клиент, сумма, оплачено/долг,
  магазин, просчёт, №/дата ТН либо её отсутствие. Поиск и фильтры «Все», «Есть долг»,
  «Не списано» сочетаются. Итоги суммы, оплаты и долга считаются по видимым строкам.
  Отметка «Списано в учётной программе» — только ручная пометка после работы
  сотрудницы в другой программе, не команда списания. Печать организации,
  доверенность и примечание раскрываются в строке как сведения, не fake-кнопки.
- Документы — возврат оригиналов **к нам**: независимые checkbox «ТН у нас» и
  «Счет у нас», фильтры «Все», «Ждём возврата», «Всё у нас». Только три оформленные
  ТН; карточка без ТН видна в реестре. Возврат не зависит от оплаты.
- DOM строк при отметках не пересоздаётся. В реестре и документах строка,
  переставшая подходить фильтру, остаётся видимой до выхода фокуса из неё;
  итог включает её. Это позволяет отметить оба оригинала без скачка фокуса.
- Три входящие — **демо ботских накладных**, бот не подключён. Поставщик, номер,
  дата, магазин, сумма и независимые read-only «Проверена / Пришла / Оплачена».
  В подробностях НДС 20% (включён в сумму), сумма без НДС и демо-источник.
- Вторичный `details` **Журнал выписки** имеет поиск, итог и раскрытие существующей
  привязки к карточке. Реестр, документы и журнал используют один массив исходящих;
  входящие поставщиков в журнал не попадают. Одна исходящая ТН — вся сумма одной
  карточки, без частичных отгрузок и неоднозначного распределения сумм.
- **Оформление №/даты — в карточке сделки (пока демо)**. Здесь выбран только просмотр
  существующих записей, редактор привязки и переход в боевую карточку не реализованы.
  Паритет с продом неполный: нет реальной оплаты/списания, печати, экспорта,
  редактирования накладных, интеграции с ботом или учётной программой.
- **Демо · изменения только до перезагрузки**. Состояние в памяти, без `fetch`,
  backend и `localStorage`. Переключение экранов сохраняет отметки до reload.
  Финансовые таблицы имеют минимальную ширину, внутренний скролл с `role=region`,
  `tabindex=0`, `aria-label`; поля — labels, элементы — `focus-visible`, обе темы.
